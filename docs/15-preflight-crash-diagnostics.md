# IMOUTO preflight crash diagnostics

## Headless startup qualification

The installed launcher accepts an explicit laboratory-only `-StartupTest` scenario. Normal launches default to `None` and clear inherited test-run environment variables. No chat command, logged-in player, fake admin identity or normal event start is used. The harness obtains the dedicated world from a non-default game instance, waits up to 120 seconds for saved base models, then runs bounded game-thread operations.

For a deliberate fresh world-based run, `-StartupTestBaseIndex N` pins the Nth saved base in the sorted registry (two-base cases select N and N+1). The index is recorded in the run plan and cannot change during qualification. An unavailable selected base blocks instead of substituting another one. The default zero preserves automatic discovery. Selecting a different base requires a new explicit launcher run after complete prior cleanup; it never changes normal online-guild admission or replays a failed native operation.

While the server is stopped, use the installed launcher with `-ValidateOnly -StartupTest SpawnCleanup`, then launch with `-StartupTest SpawnCleanup`. Available scenarios are `SpawnCleanup`, `Movement` and `TwoBaseMovement`. They use one stock level-30 bounty NPC per selected base, not a native invasion. Movement requires observed travel toward the base and arrival within the stock action's approach radius, not just a returned action handle. Cleanup requires verified termination of each exactly owned actor.

Arrival now additionally requires grounded, non-flying/non-falling movement, an owned root capsule, three-dimensional proximity to the navigation goal and feet within 150cm of that goal's height. Historical movement passes used planar proximity only; some retained samples were on another vertical level and do not establish this stronger arrival condition. Sky-base elevation alone is not an error, but matching XY above or below its intended surface is not arrival.

The planar base sampler preserves the supplied Z and does not establish collision/navigation readiness. Startup scenarios therefore require the audited 80-byte pawn-CDO floor sweep in short mode and the 104-byte bounded navigation projection before an NPC is requested. A missing floor/nav result is `blocked`, not a zero-vector spawn or permission to widen the search to the native five-kilometre long-ray mode. Private evidence retains relative height/distance and scope-failure reasons.

`-StartupTest Prewarm` independently qualifies a test-owned stationary TargetPoint, a deferred/configured WorldPartitionStreamingSourceComponent with one 12000cm spherical shape, and a 10000/12000cm navigation invoker. It changes no global streaming flags or shared CDOs and spawns no NPC. Source-enabled/completion status alone is insufficient: actual floor and navigation predicates must succeed. The test unregisters its invoker, disables the source and verifies owned helper destruction; incomplete helper cleanup retains quarantine.

NPC startup scenarios use that same bounded prewarm when their initial physical checks fail, retaining support until all test NPCs have been cleaned up. If prewarming never produces physical floor/nav readiness, the helpers are cleaned and no NPC is requested.

`-StartupTest Engagement` follows verified movement with the existing base-local combat/structure behavior. It requires a real positive server damage callback from the owned NPC to a scoped character defender, not a successful action return. Incoming damage is recorded separately and does not pass the test. No player identity is fabricated and no reward/normal event state is modified; a base with no suitable character defender can legitimately block this case.

Engagement records bounded weapon readiness, ammunition, actual gun state, aim/shoot state and the stock attack line-of-sight predicate without raw actor names or player identities. Target selection retains a visible scoped defender, or searches the bounded local roster for one before falling back to a still-scoped occluded target. A missing current action can start another encounter after the retarget interval; a remembered requested mode alone cannot establish that combat is still running. It does not restart a running action on every poll, assume that nearby means visible, or query weapon-dependent predicates before initialization. Ready weapons/action handles and a visible target are still not proof of damage.

Combat observations run at most once per second independently of the five-second engagement dispatch interval. They record outer-action timer/delta separately from inner FireMove timer/delta and shot-attempt progress, alongside stored shooter identity, aim eligibility, layer-zero flags and root-facing versus aim-point-facing. Signed movement mode/input/acceleration/velocity evidence includes the first escaped sample without further combat dispatch. These are read-only observations; they do not force aim/fire, consume movement input, change physical mode or teleport an escaped NPC.

Stock importance scheduling can produce action-component intervals up to ten seconds before applying the controller's minimum interval. Six unchanged one-second state samples therefore do not establish a broken state constructor or missing initialization. Observations record the applied component interval/enabled flag, its actual controller owner's time dilation, action active/paused state, child-action presence and state Outer identity. Scope validation also follows the child chain that can receive ticks instead of the parent. No tick, importance or clock flag is changed by these observations.

`-StartupTest ClassCatalog` resolves the exact current-build pawn class and valid PalCharacter CDO for each of the 34 audited bounty IDs, one per tick, without requesting NPCs. It separately records owned upright capsule dimensions, the walkable threshold and whether CDO nav-agent dimensions cover that shape. These IDs resolve to 32 unique pawn classes; class/CDO or template-shape availability does not by itself qualify spawning or combat for every entry.

`-StartupTest SurfaceSurvey` performs one report-only geometry inspection after local floor/nav residency is available, retaining any owned streaming helper until inspection and cleanup finish. It verifies the pinned main-world package, zero origin, ten persistent stock water actors, their instance-count inventory and a game-owned ocean-height witness. A narrowly bounded XY box spanning the authored world's full vertical bounds collects water geometry without a long ray; a separate capsule overlap records local water contacts and two-way operative collision responses. Each output is capped at 128 components, and a query clock duration above 0.25 seconds stops the survey before further queries. These are initial cost/cardinality observations, not a streaming or gameplay guarantee.

The survey uses an enclosure of measured root and authored mesh/body capsule proxies with their distinct center offsets. `templateOnly=true` and `spawnQualified=false` are mandatory even for `proxy-clear`; a completed survey never unlocks NPC creation. Unknown water representations, incomplete ocean witnesses, unqualified multi-body responses and changed bounds/origin remain explicit unsupported outcomes. Scene prewarming is separate from this full placement decision and cannot bypass the spawn token gate.

### One-instance shape experiment

`-StartupTest ShapeQualification` is a separate, explicit laboratory experiment, not a gameplay unlock. Its launcher plan pins `hunter-level30-one-instance-v1` to a fresh run and artifact. It permits exactly one `BOSS_Hunter_Rifle`, level 30, through the existing `SpawnNPCForServer` pipeline. The single-use proof belongs to that runner, exact member, base/world, artifact and location; it expires after two seconds and cannot be copied to another case/member or retried. No generic force flag exists.

**Experimental premise:** authored proxies are the controlled test envelope, not a universal final-shape certificate. The case always owns a streaming/navigation helper, rechecks residency, short CDO floor projection, walkable root support and a complete bounded same-base nav path, then performs one fresh full-column/local-capsule survey at that exact point. No failed ray is widened. Default-nav connectivity is reported when CDO agent dimensions are unqualified: it is not an exact initialized-pawn path or an instruction to travel. The survey still reports `templateOnly=true`, `spawnQualified=false`, including when the separate one-instance proof is issued.

Site selection precedes that single experiment attempt. It reuses the bounded placement search: the preferred point plus at most sixteen same-height in-base alternatives, with at most two candidate slots per poll and the existing `allowInBaseFallback` policy. Every tested site requires fresh class-specific floor/nav projection, a nonpenetrating walkable support/clearance result, the full same-base envelope, a complete bounded path and a local full-body-proxy prefilter. Duplicate inputs and projections within 1cm are skipped rather than retrying a rejected site. A failed floor does not silently retry the base origin. During selection, helper residency checks read only streaming status, not the rejected preferred floor; they do not claim physical readiness. Streaming flaps pause the existing cursor, within the same 120-second preparation deadline.

The local prefilter and full survey share the same capsule-query, component-scope and contact classifier, with **separate physical-root and water-envelope roles**. The prefilter performs two bounded local `CapsuleOverlapComponents` queries: no full-height column, world water inventory or ocean-height qualification. Physical blocking is tested using the full measured **root capsule at the proposed root position**, without an offset or size reduction. The larger authored body/mesh enclosure is still queried at its exact center offset for water contacts. Current Hunter inputs are root radius/half-height 30/30cm and water-envelope radius/half-height 30/95cm, center +62cm, lower foot -33cm. Neither envelope is lifted or shrunk.

Separating those roles requires the owned template's main skeletal mesh to have collision enabled **0**, object type **0**, profile **NoCollision**, and all 32 operative responses **Ignore**. Its class, exact owner, attachment to the measured root, unit scale and upright authored transform are checked. The template root is remeasured and its owner/transform checked as well. Unknown, enabled or changed mesh policy is unsupported, not a profile-name fallback. The policies and raw/expected root responses must agree across local filtering, the captured planned template and the final full survey. Both fresh initialized MATCH samples again require the mesh's disabled operative policy plus the existing strict geometry, world-scale and ownership comparisons.

Only the physical-root query applies the root's expected two-way blocking responses: root response to a component's object type and component response to the root's type must both be Block. A known solid component touching **only** the noncolliding mesh/water envelope is recorded as a non-water contact, not an invented root blocker. There is no floor exception: a real root blocker still rejects. Water-volume/surface contacts in **either** query veto regardless of blocking response, and the full-column lower-foot/height test remains unchanged. Unknown multi-body components or unmodelled response/body semantics in either query remain unsupported. This is a limited root/owned-main-mesh policy, not a universal certificate for arbitrary additional physical components or future geometry changes.

Both proxy checks now conservatively overlay **Block on the resolved PlayerPawn object channel** in an ordinary Lua copy of the template root response vector. `GetEngineCollisionChannelByPalObjectType(2)` supplies that channel; it is not hard-coded as 16 and is not obtained from a Pal trace converter. This model can reject additional candidates but cannot make template clearance weaker. The raw template vector remains separate, and local/final clearance, the expected collision model and the spawn proof must agree on the mapping. No collision profile, response, actor or CDO is modified.

A locally blocked or unsupported site retains its rejection and advances the existing bounded cursor without consuming the single full-column survey/experiment attempt. A local `proxy-clear` result remains `localOnly=true`, `templateOnly=true`, `spawnQualified=false`: it cannot establish dry height above all water, streaming completeness or NPC permission. Only the first site passing all preconditions proceeds immediately to the still-mandatory full survey and fresh CDO correlation; a failure there never resumes the search. No capsule is shrunk, no blocking/ground collision is ignored, and no arbitrary Z offset, longer floor ray or NPC movement is introduced.

Each site's `localProxy` evidence separates `rootClearance` from `waterProxy`, including raw component counts, non-water contacts, water contacts, unqualified bodies and coarse `shape`/`staticMesh`/`instancedMesh`/`skinnedMesh`/`other` categories. `rootCapsuleComponents` and `waterProxyComponents` retain each capped query's raw count and separate clock measurements; aggregate water/unqualified counts sum observations across the queries, not unique actors. `mutualBlockers` refers only to physical-root blockers. The selected site's evidence is retained as `selectedLocalProxy`, with the pinned `physicalPolicy`. No component/actor names, absolute hit coordinates or player IDs appear in these summaries. Contact evidence must be investigated rather than assuming that the 3cm difference between the root foot and authored mesh foot explains every rejected site.

Only the first site passing these preconditions consumes the one-shot CDO/survey/spawn attempt, synchronously at that selected point. A failed survey or template correlation cannot resume the site search. Exhaustion or deadline expiry cleans the helper without an NPC. Private planning evidence records bounded candidate ordinals, duplicate/rejection counts, rejection reasons, independent start-overlap and local-proxy results, plausible short-sweep contact deltas and normals—never raw hits, hit actor names or absolute hit coordinates.

The pinned UE4SS 3.0.1 `convert_struct_to_lua_table` path copies fields with `GetNonTrivialLocal`. Its bool pusher reads the shared byte instead of applying the property's field mask/byte offset. Consequently a normal `FHitResult` blocking byte can produce **both** copied `bBlockingHit=true` and `bStartPenetrating=true`. Copied flags are retained only under `copiedHitFlags.trust="UNTRUSTED"`; neither proves its individual bit or controls support acceptance. Direct property reads and unpacked function-return booleans are different paths. No raw-memory decoding, guessed masks, reconstructed hit struct, `BreakHitResult`, or `IsWalkable` round-trip is used.

Support now independently checks `CapsuleOverlapComponents` (104-byte frame) at the exact short sweep **start**, 5cm above the proposed root, with the full measured root radius/half-height, all 32 defined object-query values, no ignored actors/filter, and a fresh plain output table. Results are capped at 128 components and a 0.25-second query-clock observation; these are post-query limits, not native allocation guarantees. Every returned component must have the correct owner/world (`Actor:GetLevel` plus `Level.OwningWorld`). Supported query-enabled shape/static-mesh components are classified using their operative response to the converted **Pal trace type 3 / vsGroundRayCast channel**, not a collision-profile name or pawn-channel/mutual-response shortcut. Instanced, skinned, other unqualified component/body types, unknown query/response modes, oversized/malformed output and foreign/worldless results cannot certify a clear start.

An actual ground-channel blocker at that start still rejects `support-penetrating`; an unqualified overlap rejects without inventing absence. A clear start only permits the original reliable sweep-return boolean, walkable normal, bounded root-contact displacement, slope-override and upward-clearance checks to continue. It does not establish water clearance or final initialized shape. This small overlap belongs to each candidate's existing two-sites-per-poll budget and is separate from the single full-column survey; faults remain latched without retry. Ordinary dry/final-shape gates and the existing one-NPC laboratory permission are unchanged.

Support-contact association is **diagnostic only**. Support evidence records bounded Time/Distance, trace-echo agreement, Location-reconstruction/distance-time errors, and signed `Proposed.Z - Hit.Location.Z` with an exact at/before-TOI predicate. Any negative signed difference—including a tiny one—remains `PAST_TOI_AMBIGUOUS`, never forgiven by the separate symmetric displacement tolerance. The exact hit component, root shape, query point, world and simple/ground-filter witness stay process-local through the local/final survey; they are not journaled. Association checks current component identity/owner/world, matching root/point/filter and a two-second freshness bound. Root reports retain raw/distinct component and blocker counts plus coarse-category counts, distinguishing exact support-component blockers from other blockers; matching an owner, name, class or asset is insufficient. `CONTACT_CANDIDATE`, `OTHER_BLOCKERS`, stale/unqualified labels and all metrics remain observations only: `contactExceptionEnabled=false` and `bodyScopeQualified=false` are explicit. Static-mesh body/contact scope is not yet certified. Root blockers, water/unknown-body vetoes and every admission result remain unchanged; no floor exception, closest-point query, extra spatial query, offset, resize or trace widening is introduced.

The copied hit's weak component pointer must be resolved exactly once with its own `Get()` method. PED's generic unwrap helper already calls `get()`; applying that first and then calling `Get()` again incorrectly treats the resolved component as another weak pointer. The `10fb2eb` failure stopped at this boundary with one noncharacter helper and no NPC intent. Its narrowly pinned disposition requires verified old-world exit, preserves the original failure/artifact prohibition, and does not claim an observed live helper despawn.

Native query breadcrumb labels are normalized separately from camel-case report field names. The `cdcff74` run stopped before its root-overlap call because its label failed breadcrumb validation; no NPC was requested. Its separate exact-run/source/artifact-pinned helper disposition also requires verified old-world exit and retains the failed artifact and original refusal evidence.

A transient loss of streaming readiness waits within the existing 120-second placement budget before the one-instance preparation attempt is consumed. This is a read-only readiness wait, not a repeat of the floor/path/survey attempt or an NPC request. Native faults still stop the run immediately.

After the handle receives its exact nonzero individual ID and the original owned actor initializes, the harness takes at most two one-second-separated read-only samples, within ten seconds. They record actual root unscaled/scaled dimensions, relative and world transforms, owned mesh/static-body parameters, nav-agent properties, movement/ground state, operative root/mesh collision responses, initialized parameter radius and the live movement component's water cache. The actual mesh offset and static authored offset remain distinct. Live cached water values are observations, never a CDO or arbitrary-point dryness certificate.

Results are `MATCH`, `MISMATCH` or `UNSUPPORTED` against the exact planned scalar/proxy inputs. Any mismatch, unsupported geometry or observed stock action proceeds to exact owned cleanup without resizing, moving or teleporting the NPC. Two matches plus verified NPC/helper cleanup pass only this instance observation; they do not cover later posture/hover changes, all skeletal collision bodies, other bounty classes or ordinary all-bounty gameplay. The case never calls PED engagement, travel, firing, scoring or rewards; native gameplay dispatch also rejects its experimental member. It does not suppress or claim control over autonomous stock AI between samples.

#### Source-qualified initialized policies

Template values and initialized policy inputs are recorded separately. Each sample retains `actual.initializationPolicy` and a derived `expectedInitialization` report with template values and predicted deltas; observed differences are not blindly whitelisted.

- **Navigation:** with the configured update-from-owner-collision flag true, initialized agent radius must match the actual scaled root radius and height must match twice the actual scaled root half-height. The owner/root links, flag and geometry remain strict. Step height must retain its configured value, including a valid `-1` sentinel. A custom false-flag setup remains unsupported; no flag is forced.
- **Root responses:** the actual owned actor must be a qualified wild NPC according to `PalUtility:IsWildNPC`. `Pawn_NoDamageFlyPal` and `PawnParts_NonBlock` root profiles are excluded, including original template provenance. Only the resolved PlayerPawn channel is predicted to change to Block; all other responses, collision-enabled mode, object type and mesh collision remain strict. The pinned response setter changes the profile label to `Custom` only when a response actually changes; that conditional `EXPECTED_PROFILE_CUSTOMIZATION` is modeled without changing the CDO/actor or looking up `Custom` as a preset. An unchanged response must retain its prior label. `Custom` never excuses an extra response change or an excluded original profile. A mapping change since placement is a mismatch. The pre-spawn overlay remains conservative even before runtime eligibility can be established.
- **Slope:** initialized floor Z must agree, within tight float-aware tolerance, with the qualified active/priority-selected `GetWalkableFloorAngleByPriority` value and stored angle. The supported angle range is 0–90 degrees; the comparison reproduces float32 radians/cosine rounding rather than comparing against the uninitialized CDO's 45-degree value. Both samples must retain the selected angle. **PED's separate placement walkability threshold is unchanged; this does not admit 89-degree spawn surfaces.**
- **Water:** the reflected `InWaterRate` property is the configured immersion target, not current immersion. `configuredImmersionTarget` must match the captured template configuration; `GetInWaterRate()` supplies `computedImmersionRate`. Exact `FLT_MAX` means `cachedPlaneStatus="NO_CACHED_PLANE"` with `cachedPlaneAvailable=false`, not a water altitude. Entered flags zero plus computed zero can match only with qualified ownership and the independent full-column dry-scene evidence. Entered flags with an unavailable plane remain `UNSUPPORTED`, even if the getter's fallback returns zero. A nonzero configured target such as 0.65 is not itself evidence of water contact.

The newly used native getters have compact qualified frames: `IsWildNPC` is 16 bytes (`Actor` object at 0, boolean return at 8); `GetCollisionProfileName` is an 8-byte name return; `GetEngineCollisionChannelByPalObjectType` is 2 bytes (Pal object-selector enum at 0, byte return at 1); `GetWalkableFloorAngleByPriority` and `GetInWaterRate` are 4-byte float returns at 0. Movement's reflected `CharacterOwner` is checked against the exact actor, and computed-policy observations require the qualified native Pal movement class rather than assuming arbitrary subclass implementations. These are read-only observations/model calculations, not settings, importance/tick changes, geometry/nav resizing, collision rewrites or water mutations. Ordinary custom/combat spawn gates remain quarantined.

### Freshly qualified one-NPC engagement

`-StartupTest QualifiedEngagement` is a **different explicit laboratory case**, with contract `hunter-level30-qualified-engagement-v1`. It is not an alias for the old `Engagement` case or permission to turn a completed `ShapeQualification` run into combat. Normal launches still select `None`; ordinary all-bounty and old combat startup placement still fail the dry/final-shape gate. The new case uses no fake player/admin, incident, normal-event admission, scores, rewards or schedules.

In its own fresh run/artifact, this case owns one retained helper and requests at most one level-30 `BOSS_Hunter_Rifle` for one exact base. It repeats the bounded site search, support/start-overlap checks, complete base-local path, conservative full-proxy local filter, full-column water survey and current initialized-policy qualification. It must collect **two actual same-actor MATCH samples in this run**, at least one second apart within the existing observation deadline. Shape-only runs still never dispatch gameplay.

The native adapter retains two process-local receipts bound to the original actor, controller, individual parameter, full instance/player ID pair, handle, runner, source/artifact, case/contract and member. The private journal receives receipt summaries; old snapshots or copied MATCH tables cannot create these receipts. After both results are durably recorded, a separate journaled arm step enters a maximum 60-second `engagement` window. Arming is single-attempt and must follow the samples promptly; no replay or generic force flag exists.

Every experimental entry to `_configure_movement`, `startup_travel` and `engage` validates the permit and reacquires current ownership. `QualifiedEngagement` uses the full normal combat-target checks, including parent and child actions and unresolved-target handling—not the shape-only observation shortcut. Stage changes, cleanup, expiry, capture, inactivity, death, mismatch or native fault end access; changing the stage back cannot restore a revoked permit. An in-base start goes directly to the guarded engagement window and never fabricates a moved count.

During that window PED uses the existing bounded base-local engagement behavior and read-only telemetry: applied AI interval/enabled state, controller time dilation, importance, action pause/child state, state-Outer identity, outer/inner timers, weapon readiness, ammunition, aim, line of sight and facing. It does not increase importance/tick rate, manipulate time, reinitialize weapons or force shots. Successful action returns, matched shapes and incoming damage do not pass the case.

PASS requires a real positive outgoing server damage callback from the still-owned permitted actor to a character in the exact intended base, plus verified owned NPC/helper cleanup. Wrong-attacker, foreign-base and pre-arm callbacks do not count. No outgoing damage, an unavailable defender, timeout or qualification failure remains truthfully BLOCKED after cleanup. A native fault stops all further native calls and preserves uncertain ownership. The launcher checks the distinct contract, fresh run, receipts, arm identity, outgoing evidence and previous-run recovery constraints; use its explicit `-ValidateOnly -StartupTest QualifiedEngagement` before any separately authorized stopped-server launch.

### Restricted one-NPC cadence trial

`-StartupTest CadencedEngagement` is a separate explicitly approved laboratory trial, not a change to stock `QualifiedEngagement`, shape-only qualification, normal all-bounty or other delivery profiles. Its immutable plan requires contract `hunter-level30-network-sphere-cadence-v1`, `capturePolicy="stock-networked-spheres-only-v1"` and fixed `cadenceSeconds=0.1`. It reuses the fresh one-base placement, full water/physical checks, two same-actor MATCH receipts and bounded 60-second engagement permission. The older qualified case retains stock cadence.

**Operational restriction:** only the audited stock normal **networked Sphere** capture route may operate on the trial NPC. Legacy wire/cage/drone/boss capture, non-RPC setup fallback, server-scripted capture, third-party capture and other ownership-transfer mechanisms are excluded during this disposable trial. This is not universal capture coverage or a generally transferable encounter lease.

During `Bridge.register`, before scheduling NPC work, the adapter qualifies and registers the native **pre-hook** for `PalPlayerController.SetupInternalForSphere_ToServer` (24B; flags `0x00220CC0`; `id` int at 0, sphere object at 8, target character object at 16). Native hook registration must return two valid distinct IDs. The callback receives exactly four RemoteUnrealParams: capturer Context, ignored id, sphere, target character. It verifies the actual game-thread predicate, exact owned target and one of the twelve recovered `NewPalSphere/BP_PalSphere_Body` classes (base plus Ancient1/2, Debug, Exotic, Giga, Legend, Master, Mega, Robbery, Tera and Ultimate). It changes no capture argument, capturer or sphere. A missing/failed barrier or thread API prevents admission and lease acquisition.

After fresh shape qualification and engagement arming, the lease captures the **original controller's PalAIActionComponent**, full ownership identity, original interval and controller minimum. A minimum incompatible with the fixed float32 0.1-second target rejects the trial without lowering it. Only the 4B `ActorComponent.SetComponentTickIntervalAndCooldown(TickInterval float@0)` setter is used, with an explicit reflected receiver and readback. The setter is applied once when needed, not on each poll; same-valued float32 readback never causes a redundant cooldown reset. No importance flag, SetActiveAI, ResetTickInterval, manual tick, time dilation, health/level, weapon initialization, aim or firing override is introduced.

Lease checks at gameplay entries and telemetry detect external/native interval overwrites. The first trial retires rather than reapplying or fighting that writer; its newer value is not overwritten, and the result is BLOCKED. On stage change, expiry, death or cleanup, generation retirement/inactivation precedes restoration. The original saved interval is restored only while the same original actor/controller/component and full ID ownership remain valid and the current value still equals the recorded lease-applied value. Restore readback is mandatory. An invalid/disposed original component is recorded as verified disposal; a live component with unreadable or transferred ownership is `UNRESOLVED`, never a fake cleanup.

At the first matching normal-Sphere RPC pre-callback, generation retirement happens **before** validation/restoration, and restoration/readback completes **synchronously before the pre-hook returns**. `ExecuteInGameThread` is never queued for this barrier. Duplicate requests, capture failure or later false/true events cannot rearm the retired generation. Off-thread calls, unknown sphere families, wrong capture context or failed old-owner checks retire/quarantine without changing a foreign object. The void pre-hook cannot cancel capture. A native fault stops further native calls; an uncertain post-apply/restore outcome retains recovery requirements.

Private startup journals record apply/restore intents, returns, float32 readbacks, generation retirement, disposal, unknown writes and unresolved outcomes without capture IDs or raw error text. Existing combat telemetry retains actual outer/inner deltas and action/weapon state; the first delivered tick can carry elapsed time from the previous stock cooldown, so it is not by itself cadence proof. PASS still requires real positive outgoing same-base character damage, verified NPC/helper cleanup, and a verified `RESTORED` or `DISPOSED` lease. A faster getter, action return or incoming damage cannot pass it. Same-valued uncoordinated writers and process failure remain explicit lease limitations.

Disposal requires a successfully observed Boolean `IsValid()==false`; an unreadable or non-Boolean validity result is not disposal evidence. Capture-target identity uses checked validity and positive integer addresses inside its own flushed boundary; only a verified address mismatch is an unrelated capture. The entire restoration transaction, including ownership-property reads, runs inside a flushed native fault boundary. An `UNRESOLVED` lease latches the native stop, including ownership or persistence failures, and prevents halt, capture, polling or unregister paths from repeating native reads. Failed restoration propagates out of ownership inspection before address or telemetry reads. Journal or snapshot failure also stops the current runner tick before further native observations, prevents recursive write attempts and retains unresolved recovery rather than reporting cleanup.

The first live cadence run on `1b3c3a2` passed both shape samples, delivered action deltas around 0.1 seconds, consumed 57 rounds including a reload, and restored the original 10-second interval with readback. All 6016 native boundaries were paired; the helper was cleaned and the NPC had a known native dead outcome. This was **BLOCKED**, not a combat PASS: no outgoing damage witness was accepted. Health and damage-hook counters were last sampled before death, so they cannot establish the final instant's cause. Startup checkpoints now retain process damage/death-hook counts and the count of pending, uncredited damage receipts through terminal transitions; these counts never substitute for a scoped outgoing-damage witness.

The counter-only follow-up on `93d8254` retained zero damage/death-hook calls and zero pending receipts through its terminal checkpoint. The NPC left the leash more than 200 metres below the base; its interval was restored, its despawn was observed, and the helper was cleaned. Additional cadence-only observations therefore separate actor activation, actual root/main-mesh overlap/collision flags, and movement activation/primary/cached intervals, gravity and last-update vectors. The actual current target is sampled only when assigned to the exact base. These are periodic read-only observations, not complete body-part or bullet/contact coverage, and they never enable overlap, physics, movement, importance or another tick interval.

Spawn/observation/cleanup intents and returns are journaled separately. Pending IDs and capture-in-progress wait boundedly without another spawn or despawn. The helper stays until NPC cleanup is verified; a native fault stops all calls and preserves uncertain ownership rather than trying another operation. Use the installed launcher's `-ValidateOnly -StartupTest ShapeQualification` before the separately authorized launch, with the server stopped. Normal launches never arm this experiment.

Actor world ownership uses the explicitly invoked Engine `Actor:GetLevel` function and reflected `Level.OwningWorld`. The pinned UE4SS actor `GetWorld`/`GetLevel` helpers walk outer objects and can misidentify streamed actors. Ten authored persistent water actors are a subset, not the world's maximum count: validated same-world streamed actors are included and checked too. Genuinely foreign/worldless results remain a stop, not a reason to discard geometry and declare completeness.

Cleanup requests are submitted for all bounded test members before waiting on any one of them. Each NPC/helper gets its own confirmation deadline measured from its own request; another actor's wait must not consume that budget. A request is never reissued while confirmation is pending. Reports distinguish observed cleanup from an explicitly certified old-world finalization.

Blueprint class wrappers are not GC roots. Reacquire the exact class and its CDO immediately before each CDO floor query, and reacquire action classes before dispatch. The two-source crash on `122eea9` reached an invalid `InClass` ancestry check at Shipping RVA `0x3173098`, before CDO/physics access; stale lifetime is consistent with the dump, but the specific invalidation mechanism was not proven. Physical probes wait for the relevant streaming source to finish, then still require real floor/nav results.

Each launch creates a fresh private `Pal\Saved\PalEventDirector\startup-tests\<run-id>` directory containing its source-pinned plan, checksummed journal and snapshot. The snapshot's payload reports `running`, `passed`, `blocked` or `failed`, the current stage, observed counts and cleanup completeness. Normal event state, including interrupted request16, is separate and is not replayed or cleared.

Native character creation has three separate milestones: a returned handle, an assigned nonzero individual ID, then an initialized actor. On the dedicated path the handle's ID can initially be zero while a creation continuation is queued. ### Concrete buffer hazard

The exact pinned [LuaUFunction header](https://github.com/Okaetsu/RE-UE4SS/blob/2281fa311e417b1dfddedbcd49972d764fddb244/UE4SS/include/LuaType/LuaUFunction.hpp) defines `DynamicUnrealFunctionData` as a fixed `uint8_t data[0x200]` stack buffer: **512 bytes**. The pinned [LuaUObject implementation](https://github.com/Okaetsu/RE-UE4SS/blob/2281fa311e417b1dfddedbcd49972d764fddb244/UE4SS/src/LuaType/LuaUObject.cpp) passes it to `ProcessEvent`, using reflected offsets without a visible `ParmsSize` capacity check. Returned structs are converted to Lua after that call.

The generated `FPalOptionWorldSettings` header contains 120 reflected fields, including strings and arrays. An x64 estimate using 16-byte FString/TArray and 8-byte FName is **520 bytes for the struct**, roughly 528 bytes including the world-context argument. That estimate is not a measured runtime `sizeof`, but it exceeds the fixed buffer and is a concrete reason **not to reproduce the settings getter blindly**.

The isolated diagnostic profile inspects only the return struct's metadata handles and field offsets, from the last field backwards. If `returnOffset + fieldOffset + 1 > 512`, it stops with an explicit oversized-return finding. A smaller observed lower bound is not a safe upper bound: the pinned [UFunction Lua bindings](https://github.com/Okaetsu/RE-UE4SS/blob/2281fa311e417b1dfddedbcd49972d764fddb244/UE4SS/src/LuaType/LuaUFunction.cpp) do not expose exact `ParmsSize`/return extent, so that case also stops rather than guessing.

The gameplay adapter removes **both** calls to this getter, including the dispatch snapshot's call. It uses the audited [GetOptionSubsystem declaration](https://github.com/localcc/PalworldModdingKit/blob/e6632458b97af0083eb81715775651b08104ef6a/Source/Pal/Public/PalUtility.h) and the [OptionWorldSettings property](https://github.com/localcc/PalworldModdingKit/blob/e6632458b97af0083eb81715775651b08104ef6a/Source/Pal/Public/PalOptionSubsystem.h). A property view does not pass the large struct through `ProcessEvent`'s fixed call buffer. The subsystem must belong to the selected world. Ordinary requests still require a readable Boolean true; admin requests observe the flag and let Palworld apply its own policy. There is never a fallback to the unsafe getter.

For optional isolated investigation, the test profile's stepped sequence follows manager verification with the option-subsystem pointer-signature audit, a separately bracketed getter call, world identity checks, the struct-view wrapper check, and the single Boolean read. It does not open or close a gameplay gate. Native invasion acceptance still requires correlated enemy-start evidence during an ordinary gameplay test.

`GetWorld` and `GetAddress` behavior is documented by the pinned [UObject binding source](https://github.com/Okaetsu/RE-UE4SS/blob/2281fa311e417b1dfddedbcd49972d764fddb244/UE4SS/include/LuaType/LuaUObject.hpp). Metadata property enumeration and offsets use only methods exposed by the pinned [UStruct](https://github.com/Okaetsu/RE-UE4SS/blob/2281fa311e417b1dfddedbcd49972d764fddb244/UE4SS/src/LuaType/LuaUStruct.cpp) and [property](https://github.com/Okaetsu/RE-UE4SS/blob/2281fa311e417b1dfddedbcd49972d764fddb244/UE4SS/src/LuaType/LuaXProperty.cpp) bindings. No raw-memory offsets, custom-property hacks, or invented size getters are used.

### Metadata iterator calling convention

The `daa7ffaa2597` dot-call repair was incorrect. The pinned [LuaMadeSimple implementation](https://github.com/Okaetsu/RE-UE4SS/blob/2281fa311e417b1dfddedbcd49972d764fddb244/deps/first/LuaMadeSimple/src/LuaMadeSimple.cpp) requires userdata as argument 1. Its [get_userdata helper](https://github.com/Okaetsu/RE-UE4SS/blob/2281fa311e417b1dfddedbcd49972d764fddb244/deps/first/LuaMadeSimple/include/LuaMadeSimple/LuaMadeSimple.hpp) then removes the receiver, leaving the callback at index 1. The receiver is not an upvalue. Correct invocation is `owner:ForEachProperty(callback)`, or `enumerate(owner, callback)` after separately obtaining the method. `UFunction::construct` registers the UStruct member functions; no cast or alternate wrapper is required by that registration path.

The iterator explicitly supports Boolean early termination. However, tracing the complete pinned stack operations reveals a narrower hazard: `get_bool(2)` removes a Boolean result, and the false branch also calls `discard_value(2)`. A false continuation therefore attempts to remove the callback result twice. The helper uses `nil` to continue and `true` to stop at the first excess property. This retains the inventory bound; it does not ignore signature mismatches.

An isolated fixture using the existing Fengari C API reproduces the receiver requirement and detects the invalid cleanup index before performing that undefined stack operation. It exercises the actual diagnostic helper with nil continuation and true termination. This is source-level evidence, not proof of the exact cause of run `1788569461`'s live Lua error or the original native crash.

Method lookup now has its own `*-properties-method` before/after boundary, separate from `*-properties` iteration. Missing/non-callable methods halt without trying another API. An ordinary Lua error identifies the operation and a fixed, privacy-safe classification; it never permits a retry or skip.

## One command, one operation

`ped diagnose-preflight` previews the next step and performs **zero native operations**.

`ped diagnose-preflight confirm-disposable-readonly <expected-step>` executes **one** requested operation, flushes its before/after markers, and returns control to the operator. Owning objects and retained handles are rechecked for liveness immediately before use on the same game-thread callback, each with separate `-liveness-N.before/after` breadcrumbs. These checks do not advance to any later diagnostic step. Inspect the requested after-marker before entering the command again. There is no bulk loop, automatic advance, native-all fallback, or execution on mod load.

The third word is mandatory: use the exact step identifier shown by preview. A missing, stale, skipped, or repeated identifier is rejected without executing anything. Token-only confirmation does not execute the next step.

The shared sequence is:

1. UE4SS version, utility lookup/validity, controller lookup/validity, existing controller-world retrieval/validity.
2. Individual `GetInvaderManager` UFunction signature metadata reads.
3. `get-invader-manager` **only**, then a separate `manager-valid` operation.
4. `manager-get-world`, its validity check, then separate manager/world address operations.
5. In the isolated profile, individual settings-function signature/return-struct metadata reads and the return-offset screen, ending in an explicit block.
6. In the test profile, optional option-subsystem signature reads, its getter/world checks, the settings property-view type, and the invasion-enable Boolean. This inspection is independent of ordinary in-game starts and does not dispatch automatically.

The first missing after-marker identifies the exact operation that did not return. For example, a surviving `get-invader-manager.after` permits the next explicit validity command; it does not run `manager-get-world` for the operator. A metadata mismatch or unreadable size is a stop condition, not permission to weaken checks.

## Breadcrumb format and privacy

The dedicated data directory receives `native-preflight-breadcrumbs.ndjson`. Each record has exactly three fields: `step`, `buildId`, and `objectValid`. Example:

```json
{"step":"1788559863-0028-get-invader-manager.before","buildId":"24575149","objectValid":true}
```

The leading run identifier and incrementing operation ordinal distinguish steps within a run. Step names are static labels/ordinal indexes, never object-derived names or IDs. `objectValid` describes the context's latest explicit validity result; lookup steps start false and do not claim validity until the separate validity operation. An after-marker means only that the operation returned and the marker was written; it is not a native invasion acceptance signal.

Automatic gameplay traces use `timestamp-ordinal-start-operation.before/after` labels. Their `objectValid` is false because a generic operation boundary makes no separate object-validity claim. They preserve multiple return values internally but never serialize those values into the breadcrumb file.

The recorder bypasses normal log-level filtering and flushes/closes the file before each native operation and immediately after return. Before-write failure means **no operation runs**. After-write failure, Lua error, invalid object, or signature mismatch halts that diagnostic session. Raw native/Lua error strings are suppressed; pointers, UIDs, object names, settings values, credentials, worlds, and result tables never enter the breadcrumb file.

On an ordinary Lua failure, the operator response includes only an allowlisted operation/cause pair such as `metadata-enumeration/receiver-required` or `metadata-method-lookup/non-string-error`. Classification inspects at most the first 1024 bytes of a string error, never stringifies non-string errors, and retains only fixed labels. Raw error text is never formatted or persisted. On native fail-fast, preserve the new breadcrumbs and crash artifacts and stop the experiment. The file is never read to resume or retry a diagnostic. A restarted mod does not run any operation until another explicit operator command. Existing `starting` and `awaiting_confirmation` event occurrences remain `recovery_required`; the diagnostic does not reset, cancel, or replay them.

## Validation scope

- Pure-Lua tests count native-operation mocks and require one operation per confirmation and zero at preview/startup.
- They cover host/build/API/tag/token/step-order gates, no raw object/error formatting, fail-closed file writes, signature mismatch, oversized/unknown settings layouts, and quarantine despite persisted enabled configuration.
- A Fengari C-API binding fixture covers explicit receivers, the pinned false-result cleanup hazard, nil continuation, Boolean early-stop bounds, and separate method-lookup/iteration markers. It does not load UE4SS or call Palworld.

This proves the writer contract, **not** recovery from a real UE4SS stack-cookie failure or native Palworld ABI safety.
- Windows PowerShell 5.1 tests validate diagnostic-only activation, backups, runtime-tamper rejection, and child-only attestation variables.
- No local test invokes a real Palworld getter, siege, native-all diagnostic, or Production operation.
